# Demanding daily puzzles

Goal: replace the easy daily fallback path with fair layered inference, shared by web and native. Hours of elapsed thinking is an editorial ambition, not a tested solve-time promise.

1. Add failing publication tests: direct concatenation cannot become a daily even with a high score; existing daily rows return unchanged; qualified boards retain uniqueness and race guarantees.
2. Add a shared conservative admission check for new rebus dailies and use it in persistence and UGC promotion. Keep AI fairness/playability checks. Raise the daily target floor to the lateral-thinking band while retaining adaptive easing within that band.
3. Independently author a new demanding reserve corpus with progressive hints, explicit reasoning, schema-compatible visuals and at least 30 unused days. Retain old boards as legacy data, never relabel them as difficult.
4. Integrate the new default reserve pool; test deterministic selection, novelty exclusions, exhaustion, 30-day availability and evaluator holdout separation. Keep published dates immutable.
5. Run focused tests, type checking, full web tests, lint and code review. Review actual puzzle representations for mobile compatibility and editorial fairness.
6. Publish the backend through the existing repository/deployment workflow if available, verify the active daily stays unchanged, and report whether deployment is live or pending. Native users receive backend puzzles without a new binary.
