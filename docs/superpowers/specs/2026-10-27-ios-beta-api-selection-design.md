# iOS Beta API Selection

## Intent

Make TestFlight builds able to use a public beta API that accepts Apple sandbox StoreKit transactions, while keeping the App Store build pointed at the production API. This allows Byron and invited testers to exercise Plus archive and practice without weakening production transaction checks.

## Goals

- Read the API base URL from the app bundle so an archived build can be configured at build time.
- Preserve `https://rebuzzle.byronwade.com` as the default for existing builds and App Store releases.
- Require a valid HTTPS origin for any override; reject credentials, paths, queries, fragments, and non-HTTPS schemes.
- Document the exact Xcode build-setting override for producing a TestFlight archive against the separately deployed beta API.
- Keep production API sandbox-transaction rejection unchanged.

## Non-goals

- Deploy or configure a Vercel beta service in this code change. No public beta API hostname or deployment credentials are available in this workspace.
- Change StoreKit verification, product IDs, API routes, user data, or production environment settings.
- Add a custom Xcode build configuration: this project is generated by XcodeGen, and a command-line build-setting override fits its existing Debug/Release scheme.

## Approach

Add `RebuzzleAPIBaseURL` to the app's generated Info.plist via an Xcode build setting whose default is the production origin. `APIClient` resolves that bundle value through a small validated helper; the injectable initializer remains available for request tests. TestFlight archives can override the Info.plist build setting with the public beta API origin. All API requests, including StoreKit-backed Plus endpoints, continue to use the same selected `APIClient.baseURL`.

The beta API must be publicly reachable, run outside Vercel Production, and have `STOREKIT_ALLOW_SANDBOX_TRANSACTIONS=true`. The backend's existing `VERCEL_ENV === "production"` sandbox rejection remains in force even if that flag is set.

## Acceptance

- Missing or malformed bundle configuration resolves to the production API origin.
- A valid HTTPS origin resolves exactly to that origin.
- Existing dependency-injected API clients keep using their injected host.
- A generated app plist contains the default production URL and accepts an explicit beta build-setting override.
- The archive instructions identify the external beta API requirements and do not imply that a beta service or TestFlight build has already been published.
