## Plus Archive Practice — source update (not uploaded)

Plus now includes a paginated archive of published past dailies. Each entry shows puzzle date, type, and difficulty without revealing the answer or explanation. A selected puzzle opens an isolated practice round with three guesses, progressive hints, answer-blind feedback, and Eve commentary. A correct guess or an explicit solution reveal shows the answer; a new round resets only its in-memory guesses and hints. The Plus archive entry is shown only after StoreKit reports a verified entitlement.

The server now verifies the Apple-signed StoreKit transaction on archive, practice guess/reveal, and practice Eve requests. It accepts the configured Plus non-consumable only for this app bundle, verifies sandbox and production JWS with Apple's App Store Server Library and Apple Root CA G2/G3, rejects refunded/revoked transactions, and fails closed if Apple verification or the revocation lookup fails. Production deployments always reject sandbox transactions. A non-production deployment accepts sandbox purchases only when `STOREKIT_ALLOW_SANDBOX_TRANSACTIONS=true`; set that only on a dedicated beta/staging backend. The iOS client sends the verified JWS from `Transaction.currentEntitlements`; access continues to follow the Apple Account's current entitlement and is not claimed by the first Rebuzzle account that uses it. Archive requests use the existing in-memory per-instance IP and user throttles.

Practice guesses now carry an HMAC-signed round token bound to the authenticated Rebuzzle user, puzzle, and unique round, valid for up to 24 hours. A release audit found that the original signed tokens could be replayed. The current source fixes this with a short-lived MongoDB record containing only the token SHA-256 digest, user/puzzle/round IDs, and expiry. Each accepted guess atomically rotates the digest; a correct guess deletes it. A TTL index removes expired records. No guess, answer, explanation, or attempt count is stored. The reveal endpoint requires the active token proving three wrong guesses, and client-supplied attempt counts alone cannot reveal the answer. Practice remains separate from daily score, streak, analytics, and progression writes.

App Store Server Notifications V2 are accepted at `/api/storekit/notifications`. Verified refund and reversal state is stored by Apple transaction ID and updated only by a newer signed notification date, so a delayed retry cannot undo a later refund reversal. Before enabling paid archive access in production, deploy this source, run the database index migration so the `practiceRoundTokens` TTL index exists, and set both production and sandbox App Store Server Notification URLs to `https://rebuzzle.byronwade.com/api/storekit/notifications` in App Store Connect. The endpoint and TTL index are not configured or deployed by this source change. TestFlight uses sandbox purchases, while the iOS app currently targets the production API; therefore Plus archive/practice cannot be tested in TestFlight until a separate reachable beta API and beta API base URL are configured. Vercel Preview is SSO-protected and is not a usable mobile beta API as currently configured.

## Plus Journal sync — source update (not deployed or uploaded)

Registered Rebuzzle accounts with current Plus access can sync private note text across devices. The native app keeps its own offline journal and an account-scoped revision checkpoint; the API stores only the account ID, puzzle ID, note text, revision, and update time. Guests retain notes locally until their guest identity is upgraded and has Plus. A sign-in to a different Rebuzzle account does not merge notes. Stale edits preserve both versions and require the player to choose the account version, this device, or a combined note. Network and entitlement failures keep local notes available. Account deletion removes server notes and the account’s local files; losing Plus stops sync but does not delete server notes. Notes are excluded from analytics, application logs, and AI prompts.
